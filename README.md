# 🎮 2048 · AI 托管版

> 零依赖、打开即玩的网页小游戏。除了标准的 2048 玩法，还内置了一个**自己实现的 AI**——
> 点一下「AI 托管」，它就会用 **Expectimax 搜索 + 启发式评估**替你玩，实测平均能合出 **2048**。

- 🕹 在线体验：https://xheng-cs.github.io/tile-2048-ai/
- 📦 仓库地址：https://github.com/xheng-cs/tile-2048-ai
- 🧪 测试：40 项单元测试 + 无头浏览器冒烟自测
- 📄 设计文档：[PLAN.md](./PLAN.md) ｜ 面试手册：[docs/INTERVIEW.md](./docs/INTERVIEW.md)

## 一、这个项目解决什么问题

1. **课间 5 分钟想玩点不费脑但要动脑的小游戏**：2048 规则人人秒懂，一局 30 秒起步，
   不用注册、不用联网、打开就能玩，手机浏览器也能玩。
2. **普通 2048 玩到 512 就很累**：所以做了 AI 托管——不想动脑时交给 AI，
   想看它怎么「思考」时按「提示」，让它只给建议、自己动手。
3. **工程层面**：它是把「迭代 → AI 开发 → 调试 → Git 提交 → 交付」这条流程走完整的一次实践，
   核心逻辑与界面彻底分离，随机性可复现，因此**连 AI 托管这种带随机的东西都能被自动化测试覆盖**。

## 二、主要功能

| 功能 | 说明 |
| --- | --- |
| 🎯 标准 2048 玩法 | 4×4 棋盘，相同数字相撞合并，合并得分累加，合成 2048 判定胜利（可继续挑战更大数字） |
| 🤖 **AI 托管** | 一键让 AI 自动游玩，慢速 / 常速 / 快速三档可调，随时停止接管 |
| 💡 **AI 提示** | 只给建议不代打：棋盘上弹出「AI 建议：↓ 向下」，1.8 秒后自动消失 |
| ↩️ **撤销** | 手滑点错可以回退，最多保存 20 步 |
| 📱 触摸滑动 | 手机上直接滑动屏幕操作，响应式布局 |
| 💾 自动存档 | 最高分与当前对局都存本地，刷新页面接着玩 |
| ✨ 动画反馈 | 新方块弹出、合并时弹跳、得分 `+N` 浮动提示 |
| 🌙 深色主题 | 跟随系统外观，移动端友好 |

## 三、★ 自主设计的实用 / 创新内容

> 这一节是项目里「不是照抄教程」的部分。

### 1. AI 托管（核心创新）：Expectimax 搜索 + 四项启发式评估

2048 有随机性（每次移动后随机冒出 2 或 4），所以不能用普通的极大极小搜索，我把
**玩家移动建模为 max 节点，随机出块建模为 chance 节点**，按 0.9 / 0.1 的概率求**期望值**，
这就是 Expectimax。局面好坏由四项启发式加权评估：

| 启发式 | 作用 |
| --- | --- |
| 空格数 | 空格越多越安全，不容易被堵死 |
| 单调性 | 同一行/列保持同一个递增或递减方向，方便把大数堆到角落 |
| 平滑度 | 相邻格子数值差越小越好，避免局面「炸开」 |
| 最大数靠角 | 最大方块待在角落时加分，这是 2048 的最优结构 |

**性能控制**：chance 节点只展开前 4 个空位，把分支因子压下来，保证浏览器里每步只要几毫秒。

### 2. 用数据调参，而不是靠感觉（`tools/bench.js`）

搜索深度不是拍脑袋定的——写了基准脚本用固定种子跑多局对比，实测数据：

| 配置 | 平均得分 | 平均最大方块 | 每步耗时 |
| --- | --- | --- | --- |
| depth=2 | 5 425 | 341 | 0.1 ms |
| depth=3 | 20 488 | 1365 | 0.3 ms |
| depth=4 | 20 407 | 1365 | 1.3 ms |
| **depth=5（默认）** | **31 251** | **2048** | **5.7 ms** |
| depth=6 | 每步要搜十万量级节点，单局以分钟计，不实用 | | |

结论：**depth=5、chance 分支上限 4** 是强度与耗时的最佳平衡点，因此作为默认参数。

### 3. 可复现的随机源 → 让「随机游戏」也能被单元测试

`board.js` 的出块、`ai.js` 的托管循环都接受一个可注入的 `rng` 参数。
测试里传入固定种子的伪随机数发生器，于是「AI 托管一整局能合出 512 以上」
这种带随机性的断言也能稳定跑通，还能断言「同一种子两局结果完全一致」。

### 4. 浏览器冒烟自测（`tools/browser-smoke.sh`）

单元测试跑在 Node 里，**证明不了「页面里真的能玩」**。所以我写了个脚本：
把断言脚本注入 `index.html` 的临时副本，用无头 Chrome 真的点按钮、真的按方向键、
真的开一次 AI 托管，最后检查有没有 JS 报错。输出示例：

```
RESULT grid_cells=16 | new_game_tiles=2 | keyboard_moved=true | undo_restored=true
       hint_visible=true | autoplay_progressed=true | autoplay_score=84 | errors=[]
```

### 5. 界面与逻辑彻底分离，且「双击即用」

`board.js`（棋盘规则）与 `ai.js`（搜索决策）是不碰 DOM 的纯函数，跑在 Node 里就能测；
界面层只负责渲染与事件。同时**不用 ES Module、不用任何构建工具**——因为 ES Module 在
`file://` 下会被浏览器 CORS 拦截，而经典脚本 + 全局命名空间（UMD-lite）既能双击打开，
也能被 Node `require`，两全其美。

## 四、运行 / 使用说明

### 方式一：直接打开（最简单）

双击 `index.html`，或把它拖进浏览器即可，**无需安装任何东西、无需联网**。

### 方式二：本地起服务（推荐开发时用）

```bash
cd tile-2048-ai
npm start          # 等价于 python3 -m http.server 8080
```

### 方式三：在线游玩

打开 https://xheng-cs.github.io/tile-2048-ai/ ，手机浏览器同样可以玩。

### 操作

| 操作 | 方式 |
| --- | --- |
| 移动方块 | 方向键 / `W` `A` `S` `D` / 手机滑动屏幕 |
| 撤销一步 | `Z` 或点「撤销」 |
| 让 AI 给建议 | `H` 或点「提示」 |
| 交给 AI 玩 | 点「AI 托管」，用右侧下拉框调速，再点一次停止 |

## 六、测试

```bash
npm test                      # 40 项单元测试（node --test，零依赖）
node tools/bench.js 5         # AI 基准：每个配置跑 5 局
bash tools/browser-smoke.sh   # 无头浏览器冒烟自测（需要本机 Chrome）
```

**单元测试覆盖**：

- 滑动压缩、相邻合并、计分累加
- **合并边界**：`[2,2,2,2]` → `[4,4]` 而不是 `[8]`；`[2,2,4,0]` → `[4,4,0,0]`（新合成的 4 不再二次合并）；
  `[4,4,2,2]`、`[8,8,8,8]` 等多组合并
- 四个方向的对称性、无效方向不产生新方块、`move` 不修改入参（纯函数）
- 固定随机种子下出块可复现、满盘返回 `null`、胜负判定、`hasMoves` 边界
- AI：评估函数偏好（空格多、大数靠角、单调）、决策一定合法、决策确定性、托管整局强度与终止性

## 七、开发流程回顾（迭代 → AI 开发 → 调试 → Git 提交 → 完成交付）

| 阶段 | 本项目对应的产物 |
| --- | --- |
| 1. 迭代 | [PLAN.md](./PLAN.md)：v1.0 最小可玩范围 → 复盘出 4 个迭代点（I-1 ~ I-4）→ v1.1 逐项落地 |
| 2. AI 开发 | 核心逻辑、AI、界面分层实现（`js/`、`css/`、`index.html`） |
| 3. 调试 | 单测抓到 2 个真实问题（见下）+ 无头浏览器冒烟验证真实交互 |
| 4. Git 提交 | 语义化提交，按迭代阶段分步：`chore` → `docs` → `feat(core)` → `feat(ui)` → `feat(ai)` → `docs` → `ci` |
| 5. 完成交付 | README、CI 绿勾、GitHub Pages 在线可玩、面试手册 |

### 调试阶段真实发现的两个问题（都记在测试代码注释里）

1. **测试断言写错了，而不是代码错了**：断言随机出块位置时，我把 `emptyCells` 的**行主序**下标 8
   误当成坐标 `(1,1)`，实际是 `(2,0)`。排查后确认实现正确，修正了断言——
   「先判断是代码错还是测试错」是调试里最容易忽略的一步。
2. **测试前提错了**：我原本构造「只有上下能改变局面」的棋盘来断言 AI 必须选竖直方向，
   结果 AI 返回了 `left`。排查发现那个局面里每行只有一个方块，**左移同样合法**（会把方块推到第 0 列），
   AI 没有错。于是改用真正的「满盘 + 每行无相邻相同 + 只有第 3 列存在上下相邻对」的局面，
   并补了一条更强的不变量测试：**AI 返回的走法永远不是空操作**。

## 八、已知取舍与后续可迭代方向

- 目前是新方块出现 / 合并的动画，**没有做方块滑动位移动画**（需要为每个方块维护身份与起止坐标）；
- AI 托管期间按方向键会先停止托管（避免「人机抢方向盘」），没有做「随时接管并继续」；
- 后续可迭代：5×5 棋盘模式、AI 对局回放（把每步决策与评估值记录下来）、
  多种启发式权重可切换（对比不同 AI 风格）、PWA 离线安装。
